## Monitor wait/notification audit

| Monitor/waiter | Guarded condition | State-changing notifier | Shutdown/failure path |
|---|---|---|---|
| `LandingRequest.awaitPermission` | `while (!granted)` | `grant` calls `notifyAll()` | ATC remains active until all Aircraft join in intended runs |
| `TakeoffRequest.awaitPermission` | `while (!granted)` | `grant` calls `notifyAll()` | ATC shutdown requested only after all Aircraft join |
| `ATCDesk.awaitNextDecision` | retries safe decision in `while (true)` | request submission, resource change, and shutdown call `notifyAll()` | returns `null` when shutdown requested and queues empty |
| `FuelTruck.awaitNextRequest` | queue empty and shutdown not requested | submit and shutdown call `notifyAll()` | exits after shutdown once queue drains |
| `FuelRequest.awaitCompletion` | incomplete and no failure | complete/fail call `notifyAll()` | interruption/failure is recorded and propagated |
| `TurnaroundState.awaitDisembarkingComplete` | disembarking incomplete and no failure | disembarking completion/failure calls `notifyAll()` | failure wakes and terminates dependent actors |
| `TurnaroundState.awaitReadyForBoarding` | cleaning or required fuel incomplete | cleaning/fuel completion/failure calls `notifyAll()` | failure prevents premature boarding and wakes waiter |
| `TurnaroundState.awaitTurnaroundComplete` | required service incomplete | every completion/failure transition calls `notifyAll()` | Aircraft interrupts and joins service actors on failure |
| `Runway.acquire` | runway occupied | `release` calls `notifyAll()` | final implementation uses ATC non-blocking allocation |
| `AirportCapacity.enter` | capacity full | `leave` calls `notifyAll()` | final implementation uses ATC non-blocking allocation |
| `GatePool.awaitOccupiedCount` | observed count differs | reservation/release calls `notifyAll()` | timed scenario-observation wait cannot block forever |

All production `wait()` calls execute inside synchronized methods/blocks and re-check their conditions with `while`.

## Shared-state and lock audit

- `Gate`, `GatePool`, `Runway`, `AirportCapacity`, `ATCDesk`, `FuelTruck`, `FuelRequest`, `LandingRequest`, `TakeoffRequest`, `TurnaroundState`, `Statistics`, and `FinalReport` protect mutable shared state with intrinsic monitors.
- Aircraft lifecycle ownership flags are confined to one Aircraft thread; externally observed Aircraft state/failure access is synchronized and read after `join()` in final runs.
- Ordinary queue/set/list collections are private and accessed only while their owning monitor is held.
- ATC holds `ATCDesk` while checking resources; Aircraft releases a resource before separately signalling `ATCDesk`, avoiding a reverse nested-lock cycle.
- `GatePool` invokes `Gate` in one direction only; no `Gate` method calls back into `GatePool`.
- FinalReport reads resources only after all Aircraft and FuelTruck work is joined, so final reporting cannot compete with active lifecycle mutations.
- Event output is serialized by the synchronized `EventLog.log` method while the actual actor thread remains the caller.
